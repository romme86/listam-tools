# Listam review follow-up — 5 September 2026

This follows the [workspace review](2026-09-05-workspace-review.md) and the request to address the remaining findings while pausing the ESP32 leaf experiment. Changes remain local and uncommitted. Nothing was deployed, released, flashed, or archived. This follow-up made no changes in `listam-hardware`; the earlier review changes and pre-existing hardware work remain intact.

## Addressed findings

| Finding | Implemented result |
| --- | --- |
| Owner re-key order regression | Newly applied membership changes require the next sequence in the committed chain. A higher-sequence forked re-key cannot jump ahead of its missing predecessor. The original opposite-order assertions now block CI, with added coverage across separate apply batches. Replaying already committed membership logs remains compatible with older accepted sequence gaps. |
| Concurrent legacy ticket / rigor change | Unstamped tickets use the configuration in their authenticated Autobase causal history, including transitive acknowledgement heads and the writer's implicit previous block. They no longer inherit a concurrently received rigor-on setting from the current apply prefix. The regression and a real two-writer merge now pass without TODO annotations. Invalid copied signatures cannot manufacture causal knowledge. Current stamped operations keep their existing path. |
| Incomplete sleep handling | One eight-second backend deadline covers socket suspension, queued/running application writes, apply work, shared-base opening, scheduled backups, and each open Autobase's public advance/flush operations. Bases drain concurrently. The reply explicitly distinguishes `safeToSleep: true` from deadline, failure, or superseded attempts; diagnostics include the status and pending work count. |
| Connections created while backgrounding | Personal, shared-list, temporary pairing, and owner-control transports register with the lifecycle coordinator and inherit its current state. A newly created connection cannot silently miss the suspend snapshot. Late native transitions retain the latest foreground/background intent. |
| Mobile foreground/background races | Mobile waits for the resume reply before requesting catch-up. Backgrounding gives Bare Kit a finite ten-second native linger; an explicit successful drain shortens it to zero. Old suspend replies cannot freeze a worklet that has already returned to the foreground. |
| Retained mobile RPC requests | Non-stream reply requests are removed from bare-rpc's retained map after completion or timeout. Lifecycle replies have a 9.5-second client budget. Tests cover 200 actual requests, timeouts, and late replies. |
| Owner-control dial leak | A connection timeout now destroys its socket and removes its open/close listeners. The owner-control DHT also participates in the mobile sleep lifecycle. |
| Mobile dependency advisories | Updated the URI decoder to 0.5.0 with a checked CommonJS/plus-decoding compatibility patch, and UUID to 11.1.1. Added checked `image-size` parser patches described below. Remaining npm audit output falls from 24 affected entries to 8 high entries, with no moderate or critical entries. |
| Fresh-install / native packaging failures | Declared `babel-preset-expo` at the Expo 54 compatible range and removed obsolete CSS-interop aliases. Fixed React Native 0.81.5's assumption that an unmarked CocoaPods cache already contains a Debug binary: the first build now extracts the archive for its actual configuration. Both native builds and both production JavaScript bundle exports pass. |
| NAT runner failure handling | A missing Docker executable now reports the intended SKIP result without an unhandled rejection from a second child-process exit listener. Added a regression to the tools gate. |

## Paused ESP32 features

A shared release constant disables the leaf experiment. Desktop hides the leaf bridge, Bluetooth provisioning, and voice controls; old saved preferences and worker requests cannot restart those services. Mobile hides the voice feature switch and leaf-pairing entry, and does not mount the pairing dialog/BLE hook. Headless ignores configured leaf/voice startup and refuses the local provision-leaf operation with `feature-unavailable`.

The underlying implementation and stored preferences are retained for a possible return to the experiment. Ordinary P2P list sharing, peer management, and headless server controls remain available. Native BLE dependencies/permission declarations are retained, but the paused pairing flow does not mount or request them.

Visual verification used an isolated desktop mock with both saved experiment preferences set to true. Neither the complete Peers & Devices page nor Settings exposed leaf, Bluetooth-pairing, or voice controls. The current layout was inspected against the project design guide and its examples; this change retains the existing settings modal rather than implementing the guide’s separate full-page concept. Screenshots: [Peers & Devices](screenshots/2026-09-05-peers-paused.png), [Settings](screenshots/2026-09-05-settings-paused.png). No real device settings were changed.

## Dependency patch maintenance

`listam-mobile/scripts/patch-dependencies.mjs` runs after installs. It checks exact package versions and patch context, is idempotent, and fails the install if an upstream change requires review. A clean `npm ci` was exercised.

The remaining eight audit entries all lead to `image-size` 1.2.1, through Expo/Metro tooling. The published advisories list no fixed release for [ICNS](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr) and [JXL/HEIF](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq). Local patches reject truncated, out-of-range, and non-progressing entry/box lengths. Child-process tests enforce a deadline on malicious inputs and retain normal PNG/ICNS behavior. The package version is not falsified, so npm audit continues reporting the upstream version despite these specific mitigations. This is not a claim that the entire image parser is free of other defects.

The same install script applies the React Native cache fix. The native build initially failed with missing DebugStringConvertible/Sealable symbols in both simulator architectures. Comparing the installed framework with a freshly downloaded, matching debug archive proved the installed cache held a different binary. Correcting the first-build extraction fixed the link without changing Expo/React Native major versions or disabling the new architecture.

## Release and verification limits

The two consensus fixes change which newly applied operations a peer admits. They require a coordinated release to all peers sharing a base; do not treat passing local tests as evidence that the live mesh already runs the new rules. Existing divergent/materialized views are not automatically repaired merely by reopening them. A recovery rollout must validate those bases before claiming historical divergence is repaired. This fixes the reported sequence-gap fork case; it does not make simultaneous restored/cloned owner-writer identities a supported operating mode.

Legacy causal validation refuses to guess when a required ancestor is missing locally: it raises `ERR_CAUSAL_HISTORY_UNAVAILABLE`. Recovery from aggressively pruned or otherwise unavailable writer history needs explicit validation before release. No aggressive per-sleep pruning was introduced.

The implemented sleep signal describes local drain at the handshake, not delivery to every remote peer or an OS guarantee of future execution. Listam still has no APNs/FCM sender or push-delivery service. This work bounds the existing app lifecycle; it does not claim to implement or test notification coalescing, rate-limited OS wake delivery, or an unavailable notification-head scenario in a deployed push system.

Exact TRY_LATER limiter behavior and the remaining upstream [relay-abort PR #292](https://github.com/holepunchto/hyperdht/pull/292) are not proven by the double-randomized-NAT test. Physical phone background/relink tests and real multi-device release verification remain necessary. ESP32 and its Rust warning migrations are excluded from this follow-up at the user's request.
